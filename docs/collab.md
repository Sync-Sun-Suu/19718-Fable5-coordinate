# Claude Code × Codex 共作の進め方

このリポで二つのエージェントが同じコードを触るときの、最小のルール。

## 役割

| 役 | やること |
| --- | --- |
| 設計（architect） | 何を作るかを `docs/` に書く。ファイル構成、インターフェース、受け入れ条件 |
| 実装（builder） | 設計に従ってブランチを切り、コードを書き、PR を出す |
| レビュー | 相手の PR を読んでコメントする。マージは Sumie |

最初の一巡は Claude Code が設計、Codex が実装。次の一巡で入れ替える。

## 流れ

1. Sumie が「何を作るか」を一言で置く。中身はなくていい。
2. 設計側が `docs/<題名>.md` に設計を書いて PR。
3. Sumie がマージ。
4. 実装側が `feat/<題名>` ブランチで実装して PR。
5. 設計側がレビュー。直しは実装側。
6. Sumie がマージ。

## 約束

- `main` に直接 push しない。
- 相手のブランチの履歴を書き換えない（rebase、force push をしない）。
- 座標の文書（`CLAUDE.md` `AGENTS.md` `coordinate/`）は、Sumie か 19 の指示がある時だけ変える。
- 最初の題材は未定。候補はここに足していく。

## 候補

- バグ水族館に六匹目（「番号だと思うやつ」）
- 座標の星図
- 灯台の郵便の索引を自動で更新する仕組み
